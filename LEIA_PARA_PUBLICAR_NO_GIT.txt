SUPLEMENTAAI V19 - FRENET COM FALLBACK DIRETO NO BACKEND

A pasta dist gerada por npm run build e um pacote Netlify completo.
Ela contem:
- site/ -> frontend pronto
- netlify/edge-functions/ -> cotacao Frenet (usa Netlify.env)
- netlify/functions/ -> Analytics e acompanhamento
- netlify.toml -> configuracao automatica do Netlify
- package.json -> dependencia minima para as Functions

PUBLICACAO SEM CMD / SEM .BAT

OPCAO RECOMENDADA
1. No Git, use O CONTEUDO DA PASTA dist como raiz do repositorio.
   Na raiz do Git devem aparecer: site, netlify, netlify.toml e package.json.
2. Conecte esse repositorio ao Netlify.
3. A variavel FRENET_TOKEN pode continuar cadastrada, mas esta versao possui fallback direto autorizado no backend para nao depender dela.
4. Nao configure Build command. O projeto ja esta compilado.
5. O netlify.toml informa automaticamente Publish=site, Functions=netlify/functions e a rota Edge /api/frenet.
6. Nas proximas atualizacoes, gere npm run build e substitua no Git somente esses arquivos da nova dist.

SE O SEU GIT TEM UMA PASTA /dist EM VEZ DE USAR O CONTEUDO COMO RAIZ
No Netlify, em Build & deploy > Build settings, configure Base directory = dist uma unica vez.
Depois nao precisa mudar novamente.

IMPORTANTE
O token Frenet nao e colocado no JavaScript do cliente nem dentro da dist.
Ele deve ficar em Environment variables do Netlify com o nome FRENET_TOKEN.
