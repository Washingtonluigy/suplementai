SUPLEMENTAAI V24 - IFOOD OAUTH DISTRIBUIDO + TESTE DE CONEXAO

A pasta dist gerada por npm run build e um pacote Netlify completo.
Ela contem:
- site/ -> frontend pronto
- netlify/functions/ifood.mjs -> OAuth, polling e status do iFood
- netlify/functions/ -> Analytics e acompanhamento ja existentes
- netlify/edge-functions/ -> cotacao Frenet ja existente
- netlify.toml -> configuracao automatica do Netlify
- package.json -> dependencias das outras Functions existentes

PUBLICACAO
1. Rode npm run build.
2. Use O CONTEUDO DA PASTA dist como raiz do repositorio Git, como nas versoes anteriores.
3. Na raiz do Git devem aparecer: site, netlify, netlify.toml e package.json.
4. Espere o Netlify publicar.

IFOOD - PRIMEIRO TESTE
1. Entre em Franqueado > Integracoes > iFood.
2. Use Preencher Teste (D).
3. Cole o Client Secret COMPLETO do portal iFood, informe o Merchant UUID da loja de teste e salve.
4. Clique Gerar codigo iFood.
5. Abra o Portal do Parceiro pelo botao, autorize o aplicativo e copie o authorizationCode.
6. Cole o authorizationCode no sistema e clique Conectar iFood.
7. Depois, no portal iFood Developer, gere um pedido de teste.
8. O painel consulta eventos automaticamente a cada 30 segundos. Tambem existe Buscar pedidos agora.

IMPORTANTE
- A integracao iFood V24 NAO usa Netlify Blobs.
- O iFood e aplicativo distribuido: NAO use client_credentials; use authorization_code e refresh_token.
- Nao precisa configurar Site ID, token do Netlify Blobs ou comandos extras para o iFood.
- OAuth/token iFood sao persistidos criptografados usando as tabelas de integracao que o projeto ja possui.
- Nao foi criada migration nova nem tabela nova.
- Antes de producao, o aplicativo Farm Tecnologia ainda precisa passar pela homologacao do iFood.
